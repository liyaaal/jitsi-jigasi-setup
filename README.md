# Jitsi + Jigasi + локальные субтитры Vosk

Установщик конфигурации для собственного Jitsi на Linux. Использует официальные Compose-файлы **stable-11248-3** (commit `fca3e3a578a1bdd527c20b9d86a31cfc362d5426`) и совместимый WebSocket-сервер Vosk. По умолчанию русский язык. Это отдельный серверный сценарий; для записи Google Meet, Zoom, Teams, Discord, Telegram и других сервисов используйте [Meeting Pro](https://github.com/liyaaal/jitsi-jigasi).

Старый вариант указывал Whisper HTTP-сервис как потоковый WebSocket backend Jigasi. Эти протоколы несовместимы. Здесь используется документированная интеграция `VoskTranscriptionService`. Для Whisper нужна отдельная совместимая streaming-инфраструктура; она не разворачивается этим скриптом.

## Подготовка

- Linux-сервер (например, Ubuntu/Debian), Bash, Git, OpenSSL, Docker Engine и Docker Compose v2 с `up --wait`.
- Домен с DNS, направленным на сервер, и публичный IPv4 для JVB. При NAT пробросьте порты.
- Свободные 80/tcp, 443/tcp и 10000/udp; доступ к GitHub, ghcr.io, Docker Hub и ACME.
- Ресурсы зависят от числа участников и модели Vosk. Полные модели могут требовать много гигабайт RAM и диска; проверьте [требования Vosk](https://alphacephei.com/vosk/server).

Docker устанавливается отдельно по [официальной инструкции](https://docs.docker.com/engine/install/). Скрипт не меняет firewall, группы пользователя, работающий Docker daemon или старые Jitsi-установки.

## Запуск

```bash
bash jitsi_install.sh configure \
  --public-url https://meet.example.org \
  --advertise-ip 203.0.113.10 \
  --email admin@example.org

bash jitsi_install.sh up
bash jitsi_install.sh status
bash jitsi_install.sh logs
```

Замените примеры своим доменом, IPv4 и email. `configure` создаёт конфигурацию в `~/meeting-pro-server`, проверяет Compose и **не запускает** контейнеры. `up` скачивает образы и запускает стек с ожиданием готовности Vosk. При первой загрузке модели ожидание может быть долгим. Наличие запущенных контейнеров само по себе не подтверждает рабочую транскрибацию — выполните проверку звонком ниже.

Для другого каталога добавляйте `--dir /полный/путь` ко всем командам. Пути с пробелами не поддерживаются. Для английской модели передайте `--vosk-image alphacep/kaldi-en:latest` при `configure`. Языковые модели и их качество отличаются. Тег Vosk `latest` изменяемый; для воспроизводимого production-развёртывания укажите проверенный `image@sha256:...` через `--vosk-image`.

Остановка без удаления данных:

```bash
bash jitsi_install.sh stop
```

## Доступ к комнатам

Официальная конфигурация по умолчанию позволяет создавать открытые комнаты. **До открытия сервера в интернете** настройте нужный вам способ аутентификации Jitsi: `ENABLE_AUTH=1`, `ENABLE_GUESTS=1`, `AUTH_TYPE=internal` или внешний провайдер, затем создайте учётную запись организатора по [инструкции Jitsi](https://jitsi.github.io/handbook/docs/devops-guide/devops-guide-docker/#authentication).

Пароли сервисов — отдельные от паролей пользователей. Скрипт создаёт все необходимые сервисные пароли, включая `JIGASI_TRANSCRIBER_PASSWORD`, и сохраняет их при повторной настройке. `.env` имеет права 600; резервные копии лежат рядом. Не публикуйте их. Автоматическое создание аккаунта JaaS отключено. HTTPS настроен через Let's Encrypt; DNS и доступность портов проверяются во время выдачи сертификата.

## Где данные

Конфигурация и данные лежат внутри каталога установки, в `config/`. Каталоги `storage/` и `tmp/` доступны rootless-контейнерам uid 1000 согласно требованиям официального релиза. Сам каталог установки закрыт от других пользователей хоста.

Транскрипты: `config/storage/transcripts/`. Веб-доступ `/transcripts/` закрыт отдельным правилом Nginx; ссылки на них в чат не публикуются. Скачивайте файлы с сервера через SSH. Отдельная запись полного аудио Jigasi выключена. ASR-порт 2700 доступен только внутри сети Compose.

## Проверка после установки

1. Откройте ваш HTTPS-домен без предупреждений о сертификате.
2. Подключите двух участников, проверьте слышимость в обе стороны.
3. Включите субтитры/транскрибацию в меню Jitsi и произнесите несколько фраз на языке модели.
4. Убедитесь, что текст появляется, завершите встречу и проверьте файл в `config/storage/transcripts/`.
5. Если текст не появился, выполните `bash jitsi_install.sh logs`. Проверьте загрузку модели Vosk, пароль transcriber и подключение XMPP.

## Обновление старого проекта

Не запускайте поверх каталога `/home/dt/docker-jitsi-meet` из старого скрипта. Создайте отдельный каталог, сохраните старые `.env` и конфигурации, остановите старый стек перед использованием тех же портов и выполните проверку новым звонком. Скрипт отказывается изменять каталог без своего маркера управления. Версия Jitsi не обновляется автоматически через `git pull`.

Jigasi-транскрибация — совместимость с существующим проектом. При долгосрочном развитии учитывайте переход Jitsi к bridge-based transcription; новую архитектуру нужно проверять отдельно.

## Проверки проекта

```bash
bash -n jitsi_install.sh test-installer.sh
shellcheck jitsi_install.sh test-installer.sh
bash test-installer.sh
```

Тест использует подставные Docker/Git и временный каталог рядом со скриптом, не поднимает сервер. Проверяет повторный запуск, сохранение паролей, отсутствие дублирующихся переменных, валидацию параметров, остановку при ошибке pull и защиту существующего каталога. Тестовый каталог сохраняется для диагностики. Compose-конфигурация дополнительно проверялась с настоящими файлами закреплённого upstream-релиза. Реальное развёртывание требует Linux-сервера, домена и проверки звонком.
